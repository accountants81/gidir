# خطة ضبط محول فواتير الضرائب

## النطاق

تطوير محول Excel إلى CSV الحالي للمبيعات والمشتريات مع الحفاظ على الشكل العام وخطوات الاختيار، المراجعة، ثم التنزيل. المعالجة تظل محلية داخل المتصفح ولا يتم رفع ملفات المستخدم.

## القواعد الأساسية المعتمدة

- الناتج 22 عموداً بالترتيب الأصلي مع الاحتفاظ بصف العناوين كما ورد في نموذج Excel.
- لا يتم اختلاق أو تغيير بيانات موجودة بصمت؛ أي تصحيح لقيمة موجودة يظهر للمستخدم ويحتاج إلى تطبيق صريح.
- القيم الناقصة تظهر كأسئلة مجمعة حسب الفاتورة أو المورد/العميل أو المنتج، مع استثناء كود المنتج وبيانات الهوية الاختيارية.
- أكواد نوع المستند والضريبة وسلع الجدول والبيان والسلعة أرقام فقط من القيم المعتمدة لكل اتجاه.
- نوع سلع الجدول يصبح 0 تلقائياً فقط عند نوع ضريبة 1 مع تسجيل التطبيع؛ وعند نوع ضريبة 2 يجب اختيار 1 أو 2.
- اسم المنتج واسم العميل/المورد والبيانات النصية لا تستبدل بتخمينات مثل 0 أو غير متوفر.
- التاريخ النهائي DD/MM/YYYY، والمبالغ أرقام فقط بالنقطة العشرية دون عملة أو فواصل آلاف غير صحيحة، وفئة الضريبة دون علامة %.
- رقم التسجيل الضريبي الموجود يجب أن يكون 9 أرقام إنجليزية بلا حروف أو مسافات أو شرطات أو أصفار فقط، ولا يسمح الملف النهائي بمخالفة معروفة.
- رقم الفاتورة لا يكون فارغاً أو صفراً أو محتوياً على مسافات/شرطات/حروف دون أن يراجع المستخدم التصحيح ويطبقه صراحة، مع تحذير من التكرار.
- قاعدة البند الواحد اختيارية وبموافقة المستخدم، وتطبق فقط على الخانات الناقصة عندما يكون صافي الصف موجوداً.
- تصفية الشهر والفواتير الملغاة اختيارية، تعرض عدد الفواتير المتأثرة قبل التطبيق، ولا تنفذ تلقائياً.
- CSV بفاصلة إنجليزية وCRLF، Windows-1256 دون BOM كخيار افتراضي، UTF-8 مع BOM كخيار إضافي، وتقسيم عند 3 MB.

## التعديلات

1. تشديد منطق القراءة والتحقق والتطبيع الآمن للأرقام والمعرفات والتواريخ والمعادلات.
2. إضافة محرر تصحيح للقيم الموجودة غير الصالحة، مع اقتراحات قابلة للمراجعة والتطبيق.
3. إضافة لوحة تصفية اختيارية للشهر والمستندات الملغاة مع تسجيل عدد الصفوف المحذوفة.
4. تحديث التقرير ليحسب الحقول المطلوبة حسب نوع المستند ويعرض المعادلات والتطبيعات والتصفية.
5. الحفاظ على واجهة التصميم الحالية مع رسائل عربية واضحة وتحسين رسائل الترميز.
6. مواءمة إصدارات React وتعريفاته، وإضافة اختبارات حدودية وتشغيل build/typecheck/E2E.

## هيكل المشروع

- `artifacts/tax-invoice-converter/src/lib/local-converter.ts`: القراءة، التحقق، التطبيع، CSV والترميز.
- `artifacts/tax-invoice-converter/src/lib/schemas.ts`: عناوين النماذج والأكواد والحقول المطلوبة.
- `artifacts/tax-invoice-converter/src/components/`: المعاينة والأسئلة والتصحيحات والتقرير والتصفية.
- `artifacts/tax-invoice-converter/src/App.tsx`: تدفق الحالة والتصدير والتنزيل.
- `artifacts/tax-invoice-converter/tests/e2e/`: اختبارات الاستخدام الواقعية.

## قرار التصميم

نحافظ على أسلوب الواجهة الحالي: لوحة عمل زجاجية داكنة/فاتحة، خطوات واضحة، لون ذهبي للإجراء الأساسي، ومحتوى عربي RTL مع إمكانية الإنجليزية. التفاعل يعرض الفرق قبل أي تعديل، والتنبيهات واضحة قبل إنشاء مسودة أو ملف نهائي.
