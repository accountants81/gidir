# نتيجة ضبط محول فواتير الضرائب

تم ضبط الموقع ليحوّل ملفات Excel الخاصة بفواتير المبيعات والمشتريات إلى CSV محلياً، مع الحفاظ على عناوين النموذج الأصلية وعدد الأعمدة البالغ 22 عموداً. لا يتم رفع ملف المستخدم إلى خادم؛ القراءة والتحقق والتصدير تتم داخل المتصفح.

## ما تم إصلاحه

أصبح الموقع يكتشف نموذج المبيعات أو المشتريات من عناوين الأعمدة، ويفحص كل أوراق Excel ويطلب اختيار الورقة عند وجود أكثر من ورقة. الصفوف الفارغة بالكامل لا تُنشئ فواتير جديدة، والمعادلات لا تُكتب في CSV؛ تُستخدم القيم المحسوبة المخزنة مع إظهار تنبيه.

تمت إضافة تحقق خاص بالأكواد، ورقم الفاتورة، والرقم الضريبي، والتاريخ، وفئة الضريبة، والكميات والمبالغ. رقم الضريبة للمشتريات إلزامي في الفاتورة العادية وإشعاري الإضافة والخصم، ويجب أن يكون 9 أرقام إنجليزية غير صفرية. أما الرقم الموجود في المبيعات فيظهر كتنبيه للمراجعة. أرقام الفواتير لا تقبل الحروف أو المسافات أو الشرطات في الملف النهائي، وتظهر القيمة والاقتراح قبل تطبيق التصحيح.

أضيفت شاشة لتصحيح القيم الموجودة غير الصالحة دون تغيير صامت، وشاشة أسئلة للقيم الناقصة. تظل قاعدة البند الواحد اختيارية ولا تُطبق إلا بعد تأكيد المستخدم. وفي المشتريات، عند وجود خطأ في الرقم الضريبي تظهر خيارات صريحة لحذف الفاتورة أو كل فواتير المورد، مع نافذة تأكيد وتسجيل القرار في التقرير. كما أضيفت تصفية اختيارية للشهر والسنة وحذف نوع المستند 3، مع عرض عدد الصفوف والفواتير التي ستُحذف قبل التطبيق.

أثناء اختبار ملفات Excel الأصلية فعلياً، تم إصلاح عرض قائمة السنة ومقارنة الشهر والسنة داخل التصفية. أصبحت لوحة التصفية تعرض السنة الحقيقية مثل 2026، وتحتفظ بالفواتير المطابقة للشهر والسنة المحددين بدلاً من حذف كل الصفوف بالخطأ.

تم تصحيح إعداد pnpm `allowBuilds` للسماح ببناء `esbuild` المطلوب في بيئة النشر. بعد التصحيح نجح أمر `pnpm run test` الرسمي، بما في ذلك التثبيت والبناء واختبارات المتصفح.

التصدير الافتراضي هو CSV بفاصلة إنجليزية ونهاية سطر Windows، بترميز Windows-1256 دون BOM وباسم ملف إنجليزي. يتوفر UTF-8 مع BOM كخيار بديل، ويُقسّم الملف تلقائياً عند تجاوز 3 ميجابايت مع تكرار صف العناوين في كل جزء.

## التحقق النهائي

نجح فحص TypeScript بلا أخطاء، ونجح build الإنتاجي، ونجحت اختبارات Playwright كاملة وعددها 18 من 18. شملت الاختبارات المبيعات والمشتريات، الورقة المتعددة، السحب والإفلات، القيم الناقصة، التصحيحات والتنبيهات، حذف فاتورة مشتريات بعد التأكيد، تصفية الشهر والسنة، العينات الواقعية، الترميز العربي، حد 3 ميجابايت، التصميم المتجاوب، تغيير اللغة والثيم، والعمل دون اتصال.

نجح أمر التسليم الرسمي `pnpm run test` بعد تصحيح إعدادات البناء، ومرّ فحص lockfile وسياسة الاعتماديات بدون أخطاء.

## التشغيل

من داخل مجلد المشروع شغّل `pnpm install` ثم `pnpm --filter @workspace/tax-invoice-converter run dev` للتطوير. وللبناء استخدم `pnpm --filter @workspace/tax-invoice-converter run build`. اختبارات الاستخدام تُشغّل من مجلد المحول عبر `./node_modules/.bin/playwright test --config=playwright.config.ts`؛ إعداد Playwright يبني النسخة الحديثة تلقائياً قبل تشغيل خادم المعاينة.
